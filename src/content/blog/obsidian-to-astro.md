글쓰기 도구와 배포 도구가 다르면 글을 쓰다가 자꾸 멈춘다. 초안을 메모 앱에 적고, 그걸 복사해서 에디터에 붙이고, 이미지 경로를 다시 맞추고, 그러다 원래 쓰려던 문장을 잊는다. 이 블로그를 만들면서 가장 먼저 정한 것은 디자인이 아니라 **글이 어디서 시작해서 어디로 가는지**였다.

## 원칙 세 가지

하나. 글은 옵시디언에서만 쓴다. 웹 에디터도, 별도 CMS도 쓰지 않는다.

둘. 파일이 진실이다. 데이터베이스나 관리 화면 없이 마크다운 파일 자체가 원본이다.

셋. 배포는 푸시로 끝난다. 빌드 버튼을 누르러 어딘가에 로그인하지 않는다.

이 세 가지를 지키면 글쓰기와 배포 사이에 사람이 개입할 일이 없어진다.

## 볼트를 저장소 안에 둔다

가장 단순한 방법을 택했다. 옵시디언 볼트를 블로그 저장소 안에 두는 것이다.

```
YoungGong0601.github.io/
├── src/
│   └── content/
│       └── blog/          ← 옵시디언 볼트
│           ├── .obsidian/     (설정, git 에서 제외)
│           ├── _templates/    (새 글 템플릿, 글로 읽히지 않음)
│           └── 글들.md
└── ...
```

볼트를 따로 두고 복사해오는 방식도 생각했지만, 복사 단계가 하나 생기는 순간 "옵시디언 쪽이 최신인가 저장소 쪽이 최신인가" 를 매번 확인해야 한다. 같은 폴더를 보게 하면 그 질문 자체가 없어진다.

`.obsidian` 폴더는 `.gitignore` 에 넣었다. 창 크기나 최근 열어본 파일 같은 로컬 상태가 커밋에 섞이면 diff 를 읽을 수 없게 된다.

> 폴더 하나를 공유하는 선택의 대가는 있다. 옵시디언이 `src` 아래의 마크다운만 보게 되므로, 블로그와 무관한 개인 메모는 이 볼트에 둘 수 없다. 나는 개인 메모용 볼트를 따로 두는 쪽으로 정리했다.

## 새 글 템플릿

매번 frontmatter 를 손으로 치면 오타가 난다. 오타가 나면 빌드가 실패하고, 실패를 확인하는 데 몇 분이 걸린다. 템플릿을 하나 만들어 두면 이 왕복이 사라진다.

```md
---
title: ""
description: ""
pubDatetime: {{date:YYYY-MM-DD}}T{{time:HH:mm:ss}}+09:00
tags:
  - 기록
draft: false
---
```

`{{date}}` 와 `{{time}}` 은 옵시디언 코어 템플릿 플러그인이 채운다. 타임존을 `+09:00` 으로 박아둔 이유는, 이 값이 없으면 UTC 로 해석되어 새벽에 쓴 글의 날짜가 하루 밀리기 때문이다.

템플릿 폴더 이름을 `_templates` 로 한 것도 이유가 있다. 콘텐츠를 읽는 glob 패턴에서 밑줄로 시작하는 경로를 제외하도록 해두면, 템플릿이 글 목록에 섞이지 않는다.

```ts
loader: glob({
  pattern: ["**/[^_]*.{md,mdx}", "!**/_*/**"],
  base: "./src/content/blog",
}),
```

처음에는 `**/[^_]*` 만 썼다가 템플릿이 글로 잡혀서 빌드가 깨졌다. 이 패턴은 밑줄로 시작하는 **파일**만 걸러내고 폴더는 통과시킨다. 뒤쪽 제외 패턴이 필요하다.

## 이미지는 어디에 두는가

세 가지 방법을 재봤다.

| 방법 | 옵시디언에서 | 빌드에서 | 선택 |
| --- | --- | --- | --- |
| `public/` 에 두고 절대 경로 | 미리보기 안 됨 | 최적화 안 됨 | 버림 |
| 볼트 안 첨부 폴더 | 미리보기 됨 | 상대 경로로 최적화 | 본문 이미지 |
| `src/assets/` 공용 폴더 | 미리보기 안 됨 | 최적화 됨 | 썸네일 |

본문에 끼워 넣는 이미지는 볼트 안에 두는 쪽이 낫다. 옵시디언에서 붙여넣기만 하면 첨부 폴더에 저장되고, 상대 경로라 미리보기도 되고 빌드 때 최적화도 된다.

썸네일은 성격이 다르다. 여러 글이 같은 이미지를 쓰기도 하고, 아예 없는 글도 많다. 그래서 공용 폴더에 두고 frontmatter 에서 지정하게 했다.

```yaml
heroImage: "../../assets/images/hero-test.jpg"
```

없으면 자동으로 생성해둔 기본 이미지가 붙는다. 글 id 를 해시해서 고르므로 같은 글은 항상 같은 그림을 받는다. 목록에서 글마다 다른 색이 보이는 편이 제목만 나열되는 것보다 눈에 걸린다.

## 배포

깃허브 액션 하나로 끝난다. `main` 에 푸시되면 빌드하고 Pages 로 올린다.

```yaml
on:
  push:
    branches: [main]
```

빌드 명령에는 검사를 먼저 넣었다.

```
astro check && astro build && pagefind --site dist
```

`astro check` 가 앞에 있는 이유는 **콘텐츠 스키마 오류를 배포 전에 잡기 위해서**다. frontmatter 에 날짜를 잘못 적거나 필수 필드를 빼먹으면 여기서 멈춘다. 어느 파일의 어느 필드가 문제인지 알려주므로 고치는 데 오래 걸리지 않는다.

한 번은 일괄 치환 정규식을 잘못 써서 글 여섯 개의 본문을 날린 적이 있다. 그때도 이 검사가 먼저 실패했고, 깨진 글이 배포되지는 않았다.

## 남은 불편

**옵시디언에서 MDX 미리보기가 깨진다.** `.mdx` 파일의 `import` 줄과 컴포넌트 태그가 그냥 글자로 보인다. 편집은 되지만 결과는 브라우저에서 확인해야 한다. 컴포넌트를 쓰는 글이 많지 않아 감수하고 있다.

**검색이 한국어 어간을 모른다.** Pagefind 는 한국어 형태소 분석을 지원하지 않는다. "만들기" 로 검색하면 "만들었다" 가 걸리지 않는다. 글이 쌓이면 다른 방법을 찾아야 할 수도 있다.

**초안 관리가 애매하다.** `draft: true` 를 넣으면 빌드에서 빠지지만, 저장소에는 그대로 올라간다. 공개 저장소이므로 쓰다 만 글도 누구나 볼 수 있다. 정말 숨기고 싶은 초안은 볼트 밖에 두는 수밖에 없다.

## 정리

이 흐름의 핵심은 단계를 줄인 것이 아니라 **판단할 일을 줄인 것**이다. 어디에 쓸지, 어느 쪽이 최신인지, 배포를 언제 누를지 고민하지 않는다. 옵시디언을 열고, 쓰고, 저장하고, 커밋하고 푸시한다.

도구를 고르는 기준도 같아졌다. 새 도구가 판단할 일을 늘린다면 기능이 좋아도 넣지 않는다.
